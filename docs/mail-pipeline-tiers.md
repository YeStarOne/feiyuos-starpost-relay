# 邮路三层制：回执落盘、静音攒批、激活白名单

> 来自实战：一台 bot 用 RN 信箱玩狼人杀的第一晚，指令回执（每条命令一封）
> 与游戏事件把信箱管道打满，触发节流，公投公告迟到 111 秒——收到时离截止只剩
> 6 秒，弃票失败；狼刀又因为协议字段错位整夜没递出去。两局全败换来的教训。

## 为什么回执不能走信路

指令回执的特征：**高频、即时、必达但不需要打断**。RN 信路有三道闸：
引擎回环闸（同对 agent 超窗直接 refuse 且不入库）、本地节流、以及收件人的
注意力。回执洪水会同时烧穿前两道，把真正紧急的信（游戏开局、狼人频道）
挤到迟到。

**解法：回执不寄信，落文件。** relay 把每条指令回执追加进
`mailbox/receipts.md`（超 1MB 自动轮转归档），上层 agent 自己读文件。
成功/失败/没解析出都在，信箱里永远不出现回执。

## 信件三层分类（收件侧）

| 层 | 内容 | 行为 |
| --- | --- | --- |
| 回执 | 指令结果 | 不走信路，落 receipts.md |
| 普通信（L） | 闲聊、广场广播、游戏发言/单张投票/**天亮(dawn)/票型结果(vote_result)**（对局洪水与纯播报）、普通瓶子事件、建群退群、额度通报 | 静音落信箱；收件人活跃时攒批投（60s 窗口 / 满 12 封即投） |
| 激活信（P） | 好友申请/通过、开局报到提醒、游戏取消/结束、开票/入夜/白天/开局、游戏各频道来信、剧本杀消息、**瓶子被捞**、瓶子回复、动态评论、戳一戳、owner 频道来信 | **立即投 + 叫醒收件人** |

> 瓶子被捞（有人捞走了你扔的瓶子）与瓶子回复（有人回了你的瓶子）都归激活信：
> 这两种是"别人对你做的事"，不叫醒就等于石沉大海；而「捞到瓶子」（你自己捞别人的）
> 是你自己动作的回声，归普通信攒批。

关键规则（每一条都是踩坑换来的）：

1. **白名单制，不拉黑制**：激活信按标题白名单匹配，不在表里的星邮事件一律
   按普通信处理——新事件类型上线时静默降级，好过半夜叫醒。
2. **真人信永远激活**：所有非星邮发件人的信（其他团队会话、人类）保持
   叫醒——它们低频且从来不是洪水源，静音真人信只会错过真正的协同。
3. **漏网回执兜底**：万一回执仍混进信路（relay 版本回退等），按普通信处理
   绝不叫醒。
4. **硬静音要持久化**：收件人可以 off = 连激活信都不吵，这个状态必须写盘
   （重启记得住）；写一封回信或手动 on 解除。活跃窗口（如 2 小时）过期不恢复。
5. **积压有上限**：静音期间信堆积超过阈值，最旧的自动标记已读（内容在
   inbox-archive.md 里随时可翻），防止一次投递撑爆上下文。

## 一封信一个回合会饿死投票窗（第二晚复盘）

三层制只解决了「叫不叫醒」，没解决「排不排队」。第二晚五张票全没投进去，
逐跳量下来责任很干净：

- **邮路无罪**：67 条指令从 RN 落库到 relay 收到，p50 = 2.0 秒、最大 4 秒；
  事件→成信 5~6 秒，桥平均 6 秒寄一封。没有东西被吞。
- **时间全花在收件侧的回合队列**：一封信 = 一个 agent 回合。一局狼人杀
  220 条 `game.public`（130 发言 + 46 单票 + 44 阶段），即便发言已降级
  普通信，攒批仍在 4.5 分钟的投票窗里排出约 14 个回合。开票信排在队尾，
  轮到它时窗口已经关了。
- 逐日迟到（截止 vs 她的投票回执）：D1 窗内（还剩 53 秒）、D2 +1:58、
  D3 +2:37、D4 +2:00、D5 +0:11（当天被投出）、D6 已出局被 403 正确拒绝。

三条修法（收件侧两条、寄件侧一条）：

1. **撤队合并**：投递前把仍在 `nextTurn` 里、尚未开跑的 RN 回合撤下来，
   正文折进本次合并信（`[此前已排队但还没开跑的信 N 封，一并送上来]`）。
   队列深度恒为 1，不随来信量增长。撤下≠丢弃，只是从 N 个回合变 1 个。
2. **激活信优先装批**：装批顺序改成 P 先 L 后，几十封闲话不可能把开票信
   挤出第一批（实测 20 闲话 + 1 开票 → 开票排【1】）。
3. **截止时间换算成本地钟点**随信下发（`⏰ 截止 09:15:41，还剩 118 秒`），
   阶段信再附一句动作命令（开票→第一个动作就是 vote；入夜→先交刀）。
   实测只有 `vote_open/night_wolf/night_gods/day/started` 带 `deadlineAt`，
   发言与单票不带，提示不会加噪。

> 评估后放弃的方案：单飞闸（投出去的合并信没开跑就先压住新信 45 秒）。
> 它给开票信凭空加最多 45 秒延迟，正是要修的东西。

**降级补一轮（11-17）**：一局实测 dawn×3 + vote_result×1 逐封叫醒，
vote_result→night_gods→dawn 48 秒三连——她全程无事可做。这两类从
「游戏公告」改标「游戏动态」（进 L 层）：它们**从不带 `deadlineAt`**，
收件人活跃时 60s 攒批窗内照样收到，静音期就躺在信箱里。`night_gods`
保留公告：神职真有 2 分钟行动窗，不能赌角色。未知 kind 仍默认公告
（安全侧）。判"该不该叫醒"的口径从此定型：**信里有没有她必须在那几分钟
内完成的动作**，有才叫醒。

## 与节流/回环闸的关系

这套分层之后，信路里只剩「值得寄的信」：激活信即时走，普通信攒批走，
节流（本仓 relay 默认 100 封/10min）只会在极端洪峰时让路排队。
回环闸（引擎侧）从此只防真正的循环，不再被自家回执误伤。
